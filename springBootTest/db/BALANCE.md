## 一、设计目标

| 目标 | v0 实况 | v1 结果 |

## 三、魔窟规则

| 项 | 值 | 位置 |
|---|---|---|
| 单次未收存量上限 | 12 小时 | `DenRule.CAP_HOURS` |
| **每日累计结算上限** | **12 小时** | `DenRule.DAILY_CAP_HOURS` |
| 记账列 | `collect_date` / `collected_sec` | `demon_den`（v1 新增） |
| 聚煞阵 | 2 × 等级 煞气/h → 满级 20/h | `DenRule.SHA_PER_HOUR` |
| 魔晶矿 | 2 × 等级 魔晶/h → 满级 20/h | `DenRule.COIN_PER_HOUR` |
| 血玉髓脉 | 100‰ × 等级/h → 满级 1 玉/h | `DenRule.JADE_MILLI_PER_HOUR` |
| 心魔折损 | ≥60 聚煞 ×0.8；≥80 ×0.6（只罚煞气） | `DenRule` |
| 开辟费 | 聚煞/矿各 30 魔晶；髓脉 2 血玉 + 凝煞境 | `DenRule` |
| 升级费 | 聚煞/矿 `30×L²` 魔晶（满级共 8550） | `UPGRADE_COIN_FACTOR` |
| 髓脉升级费 | `ceil(L²/4)` 血玉（满级共 **75**，v0 为 145） | `UPGRADE_JADE_HALF` |

> 每日封顶的语义：`computePending` 取 `min(实际经过, 单次存量上限, 当日剩余额度)`；
> `collect` 成功后把本次结算秒数累加进 `collected_sec`，跨日自动清零。
> 后台「回拨上次收取」会同时把当日额度重置为 0，便于演示与补发。

## 七、v1.1 每日循环与收益递减

> 定案：2026-11-05　用户选定「**满额不变 + 超额递减**」——v1 预算表的
> 100 煞 / 80 晶、40 煞 **一个数字都没动**，只是从「前两天一次性」变成「天天拿得到」。

### 递减曲线（`common/DailyDecay.java`，唯一实现）

| 当日第 n 次 | 论道（fullLimit=10） | 研读（fullLimit=5） | 收益 |
|---|---|---|---|
| 1 ~ fullLimit | 1-10 论 | 1-5 篇 | **100%**（与 v1 预算一致） |
| 其后一档（长 `ceil(fullLimit/2)`） | 11-15 论 | 6-8 篇 | 50% |
| 再后一档 | 16-20 论 | 9-11 篇 | 25% |
| 再往后 | 21+ 论 | 12+ 篇 | 0%（仍可操作，无赏） |

- 论道题库 20 题、同一题每日一次，故实际最多 20 论/日，0% 档为兜底。
  满额 10 论全对 = **100 煞 + 80 晶**；刷满 20 论再添约 **40 煞 + 30 晶**（微量，不计入预算）。
- 研读全库 100+ 篇、同一篇每日一次；满额 5 篇 = **40 煞**，刷到 11 篇再添约 **18 煞**。
- 答对所得、答错反噬、魔晶之赏**都按当次档位递减**；档位 0 时不奖不罚。
- 次数记在 `demon_user.quiz_count_today / read_count_today`，跨子夜归零。

### 判重与榜单

| 表 | v1 | v1.1 |
|---|---|---|
| `demon_quiz_record` | `uk_user_debate(user,debate)` 终身一次 | `uk_user_debate_day(user,debate,quiz_date)` |
| `demon_read_record` | `uk_user_ref(user,module,ref)` 永久去重 | `uk_user_ref_day(...,read_date)` |
| 论道榜 | 累计答对条数 | **DISTINCT debate_id**（上限 = 题库数 20） |
| 图鉴收集度 | `COUNT(*)` | **`COUNT(DISTINCT module, ref_id)`** |

### 道具每日使用上限

`demon_item.daily_use_limit`（`-1` 未初始化 / `0` 不限 / `>0` 件数），
由 `demon_item_use(user_id, item_id, use_date, qty)` 记账，`ItemUseLimitService` 统一裁决：

| 道具 | 限购 | 限用/日 | 道具 | 限购 | 限用/日 |
|---|---:|---:|---|---:|---:|
| 聚煞丹 | 5 | 5 | 秘境罗盘 | 2 | 2 |
| 血煞丹 | 3 | 3 | 洗髓露 | 1 | 1 |
| 凝神符 | 2 | 2 | 深渊魔珠 | 1 | 1 |
| 聚宝囊 | 3 | 3 | 无上道果 | 1 | 1 |
| 悟道机缘 | 不限 | **3** | 死战悟道 | 不限 | **3** |

- 默认「限用 = 限购」，不限购的破关两枚钥匙另设 3/日；后台可逐物调。
- 覆盖两个入口：`ShopService.use`（丹符奇物）与 `ArtService.consumeItem`（破关钥匙）。
- 占用额度在扣袋之前；扣袋或效果结算失败会退回额度与背包，不会「东西没了、效果没到」。
- 结论：**日产预算不再能被囤货一次性击穿**，v1「无道具加成」的口径对长期也成立。

## 八、道途成就与今日修行（P0，纯荣誉层）

**此层不改变上表任何一个数字。** 成就解锁只给称号、徽记与道途分期进度，
**不发魔晶 / 血玉 / 煞气，不改任何产出或消耗常量**，因此不进每日预算、
不产生一次性奖励冲击，也不需要重算本表。

- `demon_achievement`：25 条可后台 CRUD 的成就定义（`cond_type` 白名单由
  `AchievementService` 判定），`status=0` 停用；种子用 `INSERT IGNORE`，不覆盖后台手改。
- `demon_user_achievement`：`(user_id, achievement_id)` 唯一，读接口时自动判定并落库，
  玩家无需领取；已解锁记录不因停用或删除定义而回退。
- 「今日修行」七课（焚香 / 参悟 / 论道 / 切磋 / 研读 / 秘境 / 洞府收取）**只读现有计数**，
  不新增任何产出通道，纯粹把 `BALANCE.md` 第二节的日活清单可视化。
- 唯一与数值有关的是 `daily_all` 成就：条件为「七课当日全满」，是从既有上限派生的判定，
  不产生新收益。
- v1.2 起首枚「初入魔道」由 `exp>=50` 改为 **`sign_total>=1`（首次焚香）**：
  开局礼包直接给 120 煞，旧条件会让新号注册即点亮徽记、下一目标跳到「魔尉之阶」（3000 煞），
  反而失去近期目标。改成行动型后形成「登录 → 焚一炷香 → 得第一枚徽记」的正反馈。
  七课「秘境」上限仍按**九处正境**求和（19 次），`newbie_only=1` 的入门试炼不计入，
  否则新兵期结束后该课永远打不满。

## 九、入魔道（v1.2 新手期，不计稳态）

> 定案：2026-11-09。**本节所有数字都不进第二节的每日预算表。**

### 为什么要做

第二节的 **895 煞 / 627 晶** 是「满级洞府 + 日活全打满」的**终局口径**，从未算过前期曲线。
注册实际是 `0 煞 / 0 晶 / 0 玉 / 引煞境`，而 `Realm.FEATURE_REQUIREMENT` 把秘境与论道封到
魔卒（累计 **1200** 煞）、魔典封到魔尉（**3000**）、典册封到魔将（**6000**）；
血玉髓脉又要 `2 玉 + 凝煞`，新号前 7 日拿不到任何血玉。
结果：第一天只能焚香（**10 煞**）+ 参悟 10 篇（**50 煞**）≈ 60 煞、80 晶，
被封禁的恰是产出最高的玩法，形成「没有产出 → 解锁不了玩法」的双重死锁。

### 一次性资粮（`common/NewbieRule.java` 是唯一事实依据）

| 1 | 120 | 200 | 3 | **开局礼包**，注册即发；够开两座洞府(60) + 一部黄阶功法(100) + 开髓脉(2 玉) |
| 2 | 30 | 100 | 0 | 每日一次，不要求连续，跨日随到随领 |
| 3 | 50 | 0 | 1 | |
| 4 | 0 | 150 | 0 | |
| 5 | 80 | 0 | 2 | |
| 6 | 0 | 200 | 0 | |
| 7 | 150 | 300 | 3 | 足以自择一部黄阶功法 |
| **合计** | **430** | **950** | **9** | 全部一次性，约等于满级稳态 0.5~1.5 日产出 |

开局 120 煞只到引煞境九重中的第 3 重（`layerSpan≈44`），**不跳境界**，成长感保留。

### 为什么稳态 895 / 627 一个数字都不用改

1. 礼包与七日礼是**每人一生一次**的定额，日活类收益不因它们增加。
2. 所有倍率有 14 天硬期限，由 `demon_newbie.started_at` 判定，到期 `boostActive()` 返回 false。
3. 入门试炼随新兵期消失，不留在每日 19 次秘境的预算口径里。
4. 存量账号首次访问 `/api/newbie/state` 会**懒补发**礼包并从当刻起算 14 天，
   演示库老号也能体验，但不会永久改变他们的日产。

### 实现约束（改数值时别踩）

- 发奖一律走 `CoinService.earn`（`reason=newbie`）写流水，煞气用 `exp = exp + N` 原子自增；
  **不要直接改 `demon_wallet` 或 `cultivation`**（后者会让 `layer` 与累计煞气对不上）。
- `GET /api/newbie/state` 是**唯一有副作用的读接口**（懒补发）；
  玩法结算点只能调 `NewbieService` 的 `boostActive/expMult/denMult/breakFailMult` 纯读方法。
